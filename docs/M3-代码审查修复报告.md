## 存储兼容与并发说明

`schemaVersion` 是快照格式版本，不是教学任务 `taskVersion`。由于旧格式的核心字段与当前格式一致，v0 可直接升级而无需重置 IndexedDB。迁移完成后在原会话 ID 写回 v1；失败时保留未持久化提示。未知破坏性 schema 版本不能猜测迁移，不删除原记录。相同 schema 的额外字段不阻止恢复，核心字段仍必须满足类型与状态不变量。

同一 Pinia store 内，序号与串行队列分别解决「异步选择提交顺序」和「数据库写入顺序」。两者不依赖数据库请求响应顺序，也不会把选择全局锁住。此修复不声称解决多个独立浏览器标签同时编辑同一会话的跨实例冲突；如需支持多个标签同步编辑，应另行定义数据库版本比较或租约。
