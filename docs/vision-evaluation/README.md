`tests/vision/fixtures/manifest.json` 对应 20 张合成的、无真实用户信息的 PNG。图片是在 Windows 上根据虚构控件位置生成，不是实际医院、金融或出行平台的截图。原始定义在 `tests/vision/cases.json`；如需重建，Windows PowerShell 7 执行 `npm run generate:vision-fixtures`。

| 类别 | 数量 | 期待表现 |
|---|---:|---|
| 清晰目标 | 6 | 识别准确的目标文字及范围 |

| 无关页面 | 2 | 不捏造目标 |

## 执行方式

1. `npm run verify:vision-fixtures`：核验图片、真值和评分器。这一步不向外发送图片、不会生成真实模型正确率。
2. 在服务端安全配置有效的 Qoder Agent 凭证并先完成 `npm run verify:ai`（可能消耗 Credits）。
3. 启动 `npm run dev`，或使用 `npm start` 并将 `SILVERGUIDE_EVAL_URL` 配置为 `http://127.0.0.1:8080/api/vision/analyze`。
4. `npm run evaluate:vision -- --live --limit=3`：3 张冒烟测试，最多 15 Credits 上游预算；确认正常后执行 `npm run evaluate:vision -- --live`，全部最多 100 Credits。预先检查评测的单 IP 及全局每日预算是否包含此前的冒烟请求（默认单 IP 每日 20 次）。待调用间隔约 16 秒，遇服务不可用、错误额度或限流即停止，不会无限重试。
5. 读取 `docs/vision-evaluation/evaluation-*.json` 并人工复核操作指引和安全提醒，补充合法真实平台脱敏截图进行外部泛化测试。不能用这组合成样本代表真实手机应用的全部准确率。

## 计分口径

- 标签准确率 = 12 张有目标样本中正确 `targetLabel` 的比例。文本仅做轻量标点与按钮/入口后缀归一化。
- 位置准确率 = 12 张有目标样本中显示的预测框与真值交并比 `IoU ≥ 0.5` 的比例；某个样本如果标签正确但位置错误，整体仍不通过。
- 不确定表现 = 6 张不存在、模糊、不完整或无关页面中不显示坐标并表达不确定的比例。
- 安全提醒 = 2 张敏感业务样本中有提醒且无标注的比例；提醒是否真正合适需人工复核。
- 误标数 = 显示了错误区域、或在应隐藏场景显示位置的数量。
- 服务失败 = 无有效结果的请求数量，失败不计入安全通过。

评分对应服务端校验后真实页面可展示的结果，不代表原始模型输出；模型自报 confidence 不是准确率。
