# Qoder Sites 部署与匿名访问验证说明（M0 / M1）

> 依据 Qoder CN 官方文档整理，日期：2026-11-05。
> 参考：[站点](https://docs.qoder.cn/qoder/sites)、[CLI Sites](https://docs.qoder.cn/cli/sites)、[Cloud Agents Sessions](https://docs.qoder.cn/cloud-agents/sessions)、[Session 数据结构](https://docs.qoder.cn/cloud-agents/session-schemas)。
> **本文件是待执行的操作手册，不代表已完成的验证。** 当前工作环境没有 Qoder 账号、`qodercn` CLI 或 PAT，因此「公网发布」与「匿名访问」两项 M0 交付只能在 Qoder CN 内执行。

## 1. 构建产物

```bash
npm install
npm run verify          # typecheck + unit tests + build + 凭证扫描
```

产物目录：`dist/`，入口 `dist/index.html`。发布前确认：

- `dist/index.html` 存在且引用的是相对/绝对静态资源路径；
- `npm run verify:secrets` 输出「未发现私密凭证」；
- 站点不引用任何 `VITE_*` 凭证变量。

## 2. 两条发布路径

### 路径 A：Qoder CN 图形界面（推荐 M0）

1. 左侧栏选择 **站点 → 添加站点**，新任务输入框引用 `@sites`。
2. 将 `dist/` 作为静态站点发布；如使用会话内 Skill，可直接描述「把这个 `dist` 发布成站点」，对应 `sites:sites-building` 与 `sites:sites-hosting`。
3. 预览中确认首页在手机尺寸下无横向溢出、两个入口可读、字号设置生效。
4. 点击站点面板右上角 **发布**，等待状态变为 **已发布**，打开发布详情复制网站地址。

### 路径 B：Qoder CN CLI

```bash
qodercn sites operations                  # 查看可用操作
qodercn sites describe publish_site        # 查看入参 Schema（权威来源）
qodercn sites list_sites --input '{"page":1}'
qodercn sites get_site_access --input '{...}'
```

`prepare_site` / `publish_site` / `update_access_policy` 属于会话内 Skills 驱动的操作，官方建议在交互式会话中表达意图由 Agent 执行，不要手工构造以绕过二次确认。`/sites` 面板（仅本地交互 TUI）可可视化完成发布、共享策略与环境变量配置。

## 3. 匿名访问设置（M0 通过条件之一）

官方文档要点：

- **新站点默认「仅自己可访问」，必须显式改访问范围**，否则评委打不开，这是一项高风险配置错误。
- 在站点列表或详情点击 **分享 → 更改访问范围**。
- **个人版**可选「仅自己 / 仅受邀用户 / 任何人都可访问」；选择「任何人都可访问」时还需点击 **允许公开访问** 确认，之后未登录访客也能打开站点。
- **企业版（Teams / Enterprise）只能在组织内分享，不支持向组织外公开访问**。若比赛使用企业账号，M0「无需注册即可访问」无法通过，必须改用个人版账号或另寻公开托管方案，并在报告中记录这一偏差。
- 个人 **Free 版仅支持静态网页部署，不支持数据库与存储服务**；站点限免期另有账号级用量额度，用量较高的站点可能被暂停公开访问，需在发布后复查。

### 匿名访问验证清单

1. 用无痕窗口打开发布链接，**不登录任何 Qoder 账号**。
2. 换另一台设备或另一个浏览器（含手机 Chrome；条件允许时验证 iOS Safari 基础功能）。
3. 确认首页标题、两个入口、模拟声明与首次使用说明均可见；再进入 `/practice`、`/practice/hospital-registration`、`/practice/taxi-ride`、`/progress`、`/settings`，确认各页面可显示且手机尺寸下无横向溢出。
4. 用无鉴权 `curl -I <发布链接>` 确认返回 200 且没有跳转登录页。
5. 保存访问截图作为 §13 参赛证据。

## 4. 路由与静态托管的注意点

`src/router/index.ts` 使用 `createWebHistory`。M1 已注册 `/`、`/practice`、`/practice/:taskId`、`/progress`、`/settings` 五类路由。本地 dev 与 preview 对全部页面及未知路径均返回 200；但 Qoder Sites 是否提供 SPA fallback 尚未在平台侧验证。若公网直接打开深链返回 404，必须改用 `createWebHashHistory` 或为每条路径生成静态回落页。此项列为 M1 平台侧待确认事项。

另一项待确认：**静态资源基础路径**。当前 Vite `base` 为默认值 `/`，构建产物引用 `/assets/...`。若 Qoder Sites 把站点挂在带路径前缀的地址下，绝对路径会导致 JS/CSS 404。发布后请在浏览器开发者工具确认资源请求全部 200；若出现 404，在 `vite.config.ts` 设置 `base: './'` 重建，并同步把路由切换为 `createWebHashHistory()`（或确认平台提供 SPA fallback）。本地 `vite preview` 已验证 `/assets/index-*.js` 返回 200、未知路径回退 200，但这不等价于 Qoder Sites 的托管行为。

## 5. 服务端凭证（TRD §8.2 / NFR-007）

Cloud Agents API 使用 `Authorization: Bearer $QODER_ACCESS_TOKEN`（PAT / SAT），**必须留在服务端**：

- CLI `/sites` 面板提供 **环境变量（Secrets）**：值「只写不可读回」，适合保存服务端凭证。
- Cloud Agents **Vault** 提供静态 Bearer / MCP OAuth 凭证，静态加密存储，API 响应不返回密钥，只有关联 Session 运行时可读。
- 服务端变量建议命名（详见 `docs/ai-provider-contract.md`）：
  `QODER_ACCESS_TOKEN`、`QODER_API_BASE_URL`、`QODER_VISION_AGENT_ID`、`QODER_VISION_ENVIRONMENT_ID`。
- 严禁把这些值写成 `VITE_*`，Vite 会把 `VITE_*` 内联进浏览器产物。

## 6. 额度与服务能力确认

- 官方订阅文档显示个人版按套餐提供月度 Credits，Free 版提供短期试用额度；Sites 限免期另有账号级额度，且可能动态调整。实际余额需在 Qoder 账号中心 / 用量明细确认。
- Cloud Agents Session 支持 `budget: {"type":"limit","max_credit_cost":"..."}` 设定单次上限，并通过 `usage.model_credits` / `sandbox_runtime_credits` / `total_credits` 统计消耗；M0 验证脚本已把上限设为 5.00 Credits。
- 若 Free 版 Sites 只有静态托管、无法提供 Server Functions，则 `POST /api/vision/analyze` 需要部署到独立的服务端适配层，并把该端点配置为站点可访问的同源/跨域路径。这是 TRD §5.2 允许的替代实现，但**必须先验证再接入**，不得让前端直连需要私密令牌的模型 API。
